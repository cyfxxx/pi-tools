# 技能使用后改进机制（SKILLS-MAINTENANCE）

每次使用技能完成任务后，按本约定把执行过程中暴露的偏差反馈回技能本身，让技能随真实使用持续进化。**记录是自动的，合并进正文是有节奏的（防噪音与版本漂移）。**

## 触发时机

技能流程完成（清理阶段/最终报告产出后）时，做一次清点：

- 技能描述的步骤与实际执行**不符**（顺序、命令、路径、参数）
- 技能缺失本应覆盖的**关键步骤/坑**（本次踩过，下次必然再踩）
- 技能里的路径/命令在本环境**无效或已过时**

无偏差则不记录（"每次必用"是噪音）。

## 记录（写入 `<技能目录>/improvements.md`）

追加一条，证据导向，格式：

```
- YYYY-MM-DD | <触发任务一句话> | <偏差/发现> | <建议改动>
```

要求：
- 只记**可复现信息**：命令、路径、报错现象、上下文条件
- 不写感受、不写空洞建议、不与已有条目重复
- 拿不准是否该改正文的，也先记录（合并时裁决）

## 合并（进 SKILL.md 正文）

触发条件（任一）：

1. 该技能 `improvements.md` 未合并条目 **≥3 条**
2. 用户显式要求优化该技能
3. 改进涉及安全/正确性（如错误命令、泄漏风险）——立即合并

合并守则：

- 只改正文（步骤、清单、命令、坑）；**不动 YAML frontmatter 的 name/description**——description 注入系统提示面，改动会漂移缓存前缀（cache-guard 关注同源问题）
- 可复现、无时间戳、无个人化表述
- 合并后清空"未合并"区（已合并历史保留最近 3 条作回看）

## packs 外部包（mattpocock-skills / dg-piagent 等）

原文不动的包：**不改包内 SKILL.md 正文**，偏差记录到包级 `improvements.md`；上游更新对照（包 README 记录克隆基线）时一并裁决本地化适配。

## 与新技能草稿流程的关系

`packs/drafts/`（task-summarizer 生成全新技能）与本机制互不冲突：drafts 负责"从长任务沉淀新技能"，本机制负责"已有技能增量进化"。

## 边界

- 本机制**不注入系统提示词**（技能文件按需读取，不膨胀）
- 改进日志随 git 同步，多机共享
- 合并是人工（模型辅助）裁决动作，不自动执行
