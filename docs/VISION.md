## 1. 终极目标

构建可以自主进化的全能型私人助手。

## 2. 三大核心功能（判据化）

### 2.1 智能 — 执行任务时稳定、可靠、高效、契合用户的需求
- 判据：缓存命中率 ≥97%（已有基线）；golden tasks 全绿；任务级 token 成本不劣化；test-all.sh 全绿。

### 2.2 自主 — 尽可能减少用户中途干预；重视每一次干预
- 独立完成全流程后一次性汇报；每次 abort 均有快照留存并与用户的 corrective prompt 关联；
- 分析自身意图与用户意图的差别，沉淀为 preference/habit 记忆，不断缩小差别。
- 判据：干预率（干预次数 / 完成任务数）趋势下降；abort 快照留存率 100%。

### 2.3 进化 — 重视每一次对话、每一个任务
- 汲取教训、总结经验、优化 agent 运行。
- 判据：教训闭环四态流转（挖掘 → 入库 → 验证 → 升格/淘汰）全部有程序承载；记忆库规模受控于注入预算。

## 3. 方法论：软硬结合

- **软**：提示词、注入记忆、关键节点提示 —— 引导模型行为。概率性生效，成本低，可迭代快。
- **硬**：编写程序、设置规则、测试守门 —— 限制模型行为。确定性生效，防退化底线。

### 3.1 单向升格通道（核心纪律）
反复有效的软引导必须逐步硬化，禁止永久滞留在软层：

```
教训记忆（recurrence≥5 且验证有效）
  → 提示词规则 / AGENTS 条目（半硬）
  → 扩展逻辑或守门测试（硬）
  → 升格完成后原软引导降权/删除（控注入预算）
```

### 3.2 硬优先原则
安全边界、缓存纪律、数据完整性一律硬编码（扩展逻辑/cache-guard/test-all），禁止依赖模型自觉遵守提示词。

### 3.3 防退化第一
进化的最大风险不是慢，是退化：一条错误教训入库后会自我强化污染后续行为。
一切结构性改动以 golden tasks 为安全网；记忆写操作走"报告→确认→快照→执行→验证"。

## 5. 记忆生命周期治理规则 v1

数据源字段：`recurrence`（复现次数）、`accessedAt`、`confidence`、`source`。

- **内容域边界（2026-08-29 用户指令）**：长期记忆只存 pi 项目/用户相关内容；项目域经验（如游戏开发、外部技能包的实操经验）存对应技能包（packs/<name>/EXPERIENCE.md 或 SKILL.md），不进记忆库

- **淘汰候选**：未删除 且 recurrence≤1 且 accessedAt 距今 >180 天 且 confidence<0.7 → 报告列出；批量删除必须用户确认（授权边界见 ROADMAP §5）。
- **升格候选**：solutions/fact 类 recurrence≥5 → 进入 §3.1 升格通道评估。
- **冲突嫌疑**：标题近似或同主题反向结论 → 报告列出，由会话裁决合并。
- 脚本只读幂等；任何写操作先快照 entries.json。
