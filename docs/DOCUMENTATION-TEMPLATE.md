## 四、命名规范

| 文档类型 | 命名规范 | 示例 |
|----------|----------|------|
| 扩展 README | `README.md` | `agent/extensions/pi-web-search/README.md` |
| 技能文档 | `SKILL.md` | `agent/skills/pi-backup/SKILL.md` |
| 设计文档 | 大写+连字符 | `docs/design/VISION.md` |
| 开发文档 | 大写+连字符 | `docs/development/AGENTS-DETAILS.md` |
| 运维文档 | 小写+连字符 | `docs/operations/ENVIRONMENTS.md` |
| 维护文档 | 大写+连字符 | `docs/maintenance/OPTIMIZATION-LOG.md` |

## 五、版本信息格式

所有文档必须包含元信息表格，格式如下：

```markdown
## 元信息

| 属性 | 值 |
|------|-----|
| 版本 | v1.0 |
| 更新日期 | YYYY-MM-DD |
| 适用范围 | <适用的环境/场景> |
```

### 版本号规则

- **v1.0**: 初始版本
- **v1.1**: 小的功能更新或文档修正
- **v2.0**: 重大功能变更或结构调整
- **vX.Y**: 按需递增

### 更新日期格式

统一使用 `YYYY-MM-DD` 格式，例如 `2026-09-12`。

---

## 六、章节编号规则

- 使用中文数字：一、二、三...
- 子章节使用阿拉伯数字：1.1、1.2、2.1...
- 保持层级清晰，最多三层

---

## 七、代码块规范

- 使用 ``` 包裹代码
- 指定语言：```bash、```typescript、```json
- 保持代码块简洁，不超过 30 行

---

## 八、表格规范

- 使用 Markdown 表格
- 表头加粗
- 保持列宽一致
- 对齐方式统一左对齐

---

## 九、链接规范

- 内部链接使用相对路径
- 外部链接使用完整 URL
- 锚点链接使用小写+连字符

---

## 十、版本控制

- 每次重大修改更新版本号
- 在更新记录中记录变更
- 保持文档与代码同步
