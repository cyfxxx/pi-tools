# 人工检查清单

## 代码审查清单

不要只看 diff 表面，对每个变更文件逐项核对：

### 1. 正确性

- 分支是否覆盖边界值、空值、null/undefined、空数组/空字符串
- 错误处理路径：异常是否被捕获并给出有用信息，失败时是否回滚
- 类型转换陷阱：字符串/数字隐式转换、NaN、精度（浮点/大数）
- 循环边界：off-by-one、无限循环、死循环风险

### 2. 安全

- 输入校验：用户输入是否经过校验/清洗（SQL 注入、命令注入、XSS）
- 鉴权/授权：新接口是否缺失权限检查；越权访问风险
- 硬编码密钥、密钥落盘、日志中泄露敏感信息
- 路径穿越：拼接用户输入的文件路径是否被消毒

### 3. 资源

- 文件句柄/网络连接/数据库连接是否关闭（try/finally）
- 超时设置：外部调用是否有超时，超时后行为是否正确
- 大循环/递归深度：是否存在内存或 CPU 风险

### 4. 并发与状态

- 共享可变状态：竞态条件、重复执行副作用
- 异步：回调/promise/await 是否遗漏或错误串联

### 5. 回归影响

- 被修改 API/函数的所有调用方是否受影响（用 grep 搜调用处）
- 配置、环境变量、依赖版本变更的影响面

### 6. 可维护性

- 死代码、重复逻辑、未使用变量/导入
- 命名是否反映意图；注释是否与实现一致（过时注释）

## 仓库优化清单

### 1. 目录结构

- 每个顶层目录是否有明确职责（配置/扩展/运行时/文档/部署）
- 是否存在无归属的孤儿目录
- 嵌套深度是否合理（超过 4 层需评估）

### 2. git 管理

- `.gitignore` 是否覆盖所有运行时数据（sessions/logs/checkpoints/stats）
- 是否有不该入库的文件被跟踪（lock 文件、临时文件）
- ignore 规则是否重复或冲突
- remote URL 是否含 token（推送前必须检查）

### 3. 存储卫生

- 大文件扫描：bak/、旧工具目录、迁移遗留
- `__pycache__`、`.DS_Store`、`Thumbs.db` 等系统文件是否已忽略
- 历史大文件是否需要 filter-branch 清理

### 4. 两类文件边界

| 入库共享 | 运行时本地 |
|----------|-----------|
| 配置、源码、README | 会话、日志、统计 |
| .gitignore 规则 | 扩展 settings.json |
| 脚本、测试 | checkpoints、notes |

### 5. 文档同步

- README 的目录清单与实际一致
- AGENTS.md 的扩展清单与 extensions/ 一致
- CHANGELOG 的版本号与 package.json 一致
