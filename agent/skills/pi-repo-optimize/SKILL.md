# 配置仓库深度优化（.pi 类）

对配置仓库（目录/存储/架构层面）做完整优化：摸底 → 分级方案 → 用户确认删除类条目 → 执行落地 → 验证提交。已验证实例：2026-08-25 .pi 仓库优化（分级方案 + drafts 入库 + 仓库卫生提交 e0c708e）。

## 适用与不适用

- 适用：用户要求对配置仓库做结构/存储/架构层面的检查优化（"检查 .pi 目录""结构优化""仓库卫生""存储清理"）
- 不适用：代码正确性/回归审计（用 pi-full-audit）；单点问题排查（直接 grep/read）

## 流程

### 1. 摸底（只读）

- 目录树全览（含隐藏目录），标注每块职责：配置/扩展/运行时/文档/部署
- git status + .gitignore 核对：运行时数据（sessions/logs/checkpoints/stats）是否已忽略；lock 文件是否入库；ignore 规则是否重复
- 大文件与残留目录扫描（bak/、旧工具目录、迁移遗留）
- 明确区分两类文件：入库共享（配置、源码、README）vs 运行时本地（会话、日志、统计）

### 2. 输出分级方案

- H1 必改：结构错误、gitignore 冲突、存在丢数据/覆盖风险
- H2 建议：仓库卫生（忽略规则、去重、残留清理）、文档同步（README 与代码实际对齐）
- H3 可选：重构迁移、长期演进
- 每条附：位置、问题、改法、影响/风险

### 3. 删除类条目用户确认

- 涉及删除运行时数据或跨设备文件的条目单列，执行前逐项确认"移除/保留"
- 实例：清理方案提议移除远程主机统计文件（memory/stats/tool-use-MYPC.jsonl），用户明确保留——远程设备的统计文件即使 git 忽略也不删

### 4. 执行与验证

- 按用户确认的方案批量修改，一轮内完成同类改动
- 验证：配置仓库跑 scripts/test-all.sh 全量回归
- 文档同步：README/AGENTS.md 的目录清单与实际一致
- 提交推送前检查 remote 无 token（有则先恢复无凭证 URL）

### 5. 收尾汇报

- 按 H1/H2/H3 分级汇报落地情况，标注未执行项及原因
- 未确认的删除类条目保持原样，不擅自处理

## 关键要点

- 分析阶段只读，方案先行；执行前把"要删什么"讲清楚，让用户做决策，而不是直接删
- 运行时数据与入库数据的边界是优化重点：该入库的（lock、有效配置）补入，不该入库的（会话、统计）忽略
- 一次优化会话产出 1 个提交粒度（卫生类合并提交），避免碎提交

## 使用后改进（必做）

任务收尾时清点：执行过程与本文步骤/路径/结论的偏差。有 → 追加一条到 `improvements.md`（证据导向：命令、路径、现象，不直接改正文）。未合并条目 ≥3 条或用户要求时，合并进正文并清日志。机制全文见 `docs/SKILLS-MAINTENANCE.md`。

## 环境备注

本环境为 termux-ubuntu（proot-Distro aarch64，Android 宿主 proot 容器，uname 含 PRoot）；优化对象为 /root/.pi 配置仓库时以此为准，其他设备以自身环境为准。
