# 分级报告

## 分级标准

| 级别 | 定义 | 处理 |
|------|------|------|
| **HIGH** | 明确的 bug、安全问题、会导致功能错误 | 必须修 |
| **MEDIUM** | 边界情况、健壮性、性能、风格，依赖上下文 | 建议修 |
| **LOW** | 疑似误报、缺乏上下文、吹毛求疵 | 可选 |

## 报告格式

```
## 代码审查结果
**审查文件数**: N | **问题**: X HIGH / Y MEDIUM / Z LOW

### HIGH（必须修）
- `路径:行号` — 问题描述
  > 修复建议: ...

### MEDIUM（建议修）
- `路径:行号` — 问题描述
  > 修复建议: ...

### LOW（可选）
- `路径:行号` — 问题描述
```

## 报告示例

```
## 代码审查结果
**审查文件数**: 5 | **问题**: 2 HIGH / 3 MEDIUM / 1 LOW

### HIGH（必须修）
- `src/auth.ts:45` — SQL 注入风险：用户输入未经过滤直接拼接查询
  > 修复建议: 使用参数化查询或 ORM

- `src/utils.ts:123` — 空指针异常：未检查 null 值
  > 修复建议: 添加 null 检查

### MEDIUM（建议修）
- `src/api.ts:67` — 超时设置缺失：外部 API 调用无超时
  > 修复建议: 添加 30s 超时

- `src/db.ts:89` — 连接未关闭：数据库连接在异常时未释放
  > 修复建议: 使用 try/finally

- `src/parser.ts:156` — 性能问题：大循环中重复计算
  > 修复建议: 提取到循环外

### LOW（可选）
- `src/config.ts:12` — 未使用变量：`debugMode` 已定义但未使用
```

## 双轴结论

报告必含：`Standards 符合度：X/N 项违规 | Spec 满足度：改动是否实现发起意图（是/部分/否，附一句依据）`。

无问题时明确说明："审查完成，N 个文件未发现问题。"
