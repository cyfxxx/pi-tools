# 工程机制层：记得住 · 查得着 · 改得动

长篇真正的困难不是生成下一章，而是写到五十一百章后仍记得：谁知道什么、资源还剩多少、哪条因果债没还、哪个伏笔该收了。本文整合 chinese-longnovel-skill 的工程纪律与 ani-book-skill 的连续性账本，是写作几万字以上必备的部分。

## 一、50 章分阶段规划

- 细纲/目录每批 **≤50 章**，展开前读阶段计划、总大纲边界与已发生状态
- 明确"哪些矛盾、角色转变、伏笔必须留给后续阶段"——细纲不擅自新增总纲外主线事件
- 规划窗口双协议：当前阶段与后续 2 个 main 节点边界一起读，避免后文撞车

## 二、上下文组装顺序（每章独立组装）

按此顺序读取（只读当前任务所需，不预读其他）：

1. 项目配置 + 当前进度 + 当前计划节点（含后续 2 章边界）
2. 主角状态仓库（见 §状态回证）——*当前真实状态的权威源*
3. 阶段计划：仅确认允许的任务/商品/预算/成长循环，**不把计划当事实**
4. 最近 3 章有效正文（不区分待审/已审）
5. 最近 20 章章节总结（跨 50 章分块拼接）
6. 50 章阶段总结；每跨 200 章补读长期摘要
7. 角色档案 / 世界观 / 伏笔台账 / 文风执行表；涉早期伏笔时回读埋设原章

**有效节点条件**：有稳定 node_id、属于已提交序列、状态回证通过（可为待审状态）——未提交的草稿、孤儿文件、哈希失效候选一律不进上下文。

**无效 & 禁止**：不按目录最大数字或修改时间推断进度；同一章有多个正文文件时停止、让用户确认权威文件。

## 三、事实锁（写前闸门）

写作/审查前，把上下文压缩为**事实锁**，至少含：硬事实、时间锚、角色认知、能力与资源、系统权限/余额/库存、任务感知与判定、关系承诺、信息流、因果债、伏笔。

- 每条事实锁记录来源相对路径与锚点；来源改变则该条锁失效
- **写前闸门**：本章细纲与已发生事实冲突 → 停止，不顺着计划改写历史；不新增细纲外主线事件/角色/能力/设定/伏笔；阶段计划缺失 → 退回上游规划，不在正文里补系统设计

## 四、状态回证（状态仓库是投影，不是旁路事实）

模型：**状态仓库与章节总结是从已提交正文可重建的投影**：

```
已提交正文 → 不可变总结/状态增量 → 提交点(commit head) → 物化章节总结 + 状态仓库
```

- 正文是权威；仓库与正文冲突时，以已提交正文重建投影
- **章节总结只维护增量**（关键事件/角色状态增量/硬事实锚点/认知增量/资源增量/因果债伏笔/章末状态），不复制完整仓库；每个增量带来源锚点
- **主角状态仓库**只保留最新状态：身份位置/能力成长/资源资产/关系承诺/信息认知/目标债务/名声/后文禁止误写
- 状态仓库复杂度高时（多货币/多商店/多成长线/并行任务/跨章冷却）拆独立"系统状态仓库"，禁止双重权威
- **摘要预算**：每 50 章阶段总结（结算/时间锚/状态核对/角色进退/伏笔/未偿因果债）；每 200 章长期摘要（压缩前四份阶段总结，只留仍影响后文的事实并标失效点）
- 事实性修复后**重建受影响章节之后的状态投影**，避免"正文改了、摘要停在旧版本"

## 五、伏笔追踪与回收

- 台账收录每笔伏笔：ID / 承诺 / 埋设章 / 目标窗口 / 当前状态 / 最近推进 / 兑现证据 / 可触碰窗口
- 状态：pending（沉睡）→ advanced（推进）→ paid_off（兑现）→ stale（失效）→ retired（弃用）
- 伏笔同时进：细纲计划 / 章节总结 / 阶段摘要 / 台账——不是备注，是**待偿债务**
- 审查核对：是否**超期**（>50 章沉睡）、**变义**（承诺 A 兑现 B）、**缺因果桥**（中间没有承接）
- 计划回收时回读埋设原章及其总结；早期伏笔回读原章正文

## 六、双重审查 + 哈希绑定

- 正文稳定性：依赖稳定正文的产物顶部写 `<!-- source-hash: … | SHA256 -->`；正文指纹变 → 依赖产物标 `stale`，重新核对
- 审查 = 两份独立报告（自然化审查 + 上下文一致性审查），**都绑定同一正文哈希**——正文被改，旧报告自动失效回到待审
- 审查输出只分四类：硬伤 / 风险 / 伏笔状态 / 通过项（对应 `protocols.md§体检` 报告模板）
- 每批 ≤5 章；修复遵循最小修改原则（事实不变只更哈希与元数据；事实变了重建后续投影）
- 待审（`review_pending`）不阻断续写：它是有效的已提交事实，可进入下一章上下文

## 七、连续性账本（每章回灌）

面向章节交接与断点恢复，每章定稿后更新（吸收 ani-book）：

- **fact-ledger（事实账本）**：只收"已发生且会限制后文"的事实：稳定 ID / 事实 / 发生章节 / 证据位置 / 涉及角色 / 状态 / 后续约束
- **payoff-ledger（伏笔/承诺账本）**：同 §五台账
- **resource-ledger（资源账本）**：只记跨章影响行动边界的资源：持有人/归属/可见性/使用窗口/禁止误用（个人短期状态仍在角色档案）
- **chapter-delta**：每章变更证据——最终正文来源与指纹、审查结果、稳定事实、角色/关系/伏笔/资源变化、质量债
- **quality-debt**：只收"带警告可继续"或修复预算耗尽但正文可读的问题，标注回收窗口
- **recovery**：最后稳定章 / 下一步 / 受保护资产 / stale 资产 / 开放质量债 / 恢复前必读文件——断点恢复只认一个明确下一步

**回灌顺序**：锁定最终正文与指纹 → 写 chapter delta → 更新台账与状态 → 跑校验 → 写/清质量债 → 每 10 章或卷末 checkpoint。

**禁止**：把计划/推测/未验证证词/修复候选写进账本；不以伏笔逾期或单章小瑕疵自动触发整批重规划。
