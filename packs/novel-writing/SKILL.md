# 长篇网文工程化写作

面向多卷长篇中文小说（网文）创作的工程化写作系统。核心分工：**执笔者（用户）负责创意、世界观、文风**；本技能负责**跨章节一致性、伏笔回收、节奏与文风稳定**，把"写到几十上百章还没写崩"从靠记忆变成可检查的纪律。

**定位**：
- 不是"万能写作提示词"，而是一套可复现的长篇创作协议：规划 → 目录 → 草案 → 正文 → 体检 → 存档 的闭环流程
- 分两层：**创作层**（rules/protocols/craft 负责怎么写好）与**工程层**（engineering 负责记得住、查得着、改得动）
- 对平台无依赖：不绑定任何编辑器/客户端，核心是 Markdown 项目 + 纯 Python 校验脚本

用户与系统共同完成多卷长篇小说。系统所有行为分三层：

1. **规则（rules.md）** —— 不可违背的一致性/叙事/输出条例
2. **协议（protocols.md）** —— 响应具体指令的执行流程
3. **知识库（templates/ 起手）** —— 用户提供的世界观事实，以项目内实际文件为准

**核心原则**：规则塑造事实，事实更新规则。二者冲突时，用户知识库文件（尤其《世界基石》）时效性更高；生成行为与规则冲突时，规则优先。

## 触发条件

- 触发：用户明确处理长篇小说的大纲、规划、目录、草案、正文、体检（审查）、存档、续写，或要求保证长篇一致性/伏笔/文风稳定
- 不触发：单独的"审查""总结"等通用词；代码、文档、配置、脚本工程；短篇单次写作

## 使用流程

```
建库（templates/ → 用户填充五件知识库）
  → 大纲 → 规划/目录 → 草案 → 正文（循环）→ 体检 → 存档
```

### 每条指令的五步闭环

任何创作指令先执行最小闭环：

| 阶段 | 必做 | 失败处理 |
|---|---|---|
| 1 指令识别 | 识别指令类型、卷号、章序、范围 | 无法识别时请用户重述为标准格式 |
| 2 依赖装配 | 读取本指令所需协议/规则/技法文件 | 协议缺失时中止，不自行编造流程 |
| 3 知识库绑定 | 定位并读取《世界基石》与四件静态基石 | 缺失核心文件时报告，**禁止捏造设定** |
| 4 前置校验 | 校验蓝图、章序、实体、输出模板 | 触发对应错误或修复指令 |
| 5 交付收束 | 交付主产物 + 叙事资源仪表盘 + 续章指令 | 异常报告优先 |

### 指令路由

| 用户意图 | 主要文件 | 联动 | 说明 |
|---|---|---|---|
| 大纲 | `protocols.md§大纲` | `rules.md`、`craft.md` | 全书立意/主线/节奏/卷结构 |
| 规划 / 目录 | `protocols.md§规划与目录` | `engineering.md§50章分批` | 战役蓝图、七列表格，批次≤50 |
| 草案 | `protocols.md§草案` | `craft.md` | ≤300 字蓝图，钩子一字不差 |
| 正文 | `protocols.md§正文` | `craft.md`、`rules.md`、`engineering.md§事实锁` | 蓝图锁定 → 初稿 → 精修 → 收束 |
| 体检 | `protocols.md§体检` | `engineering.md§双重审查` | 五类扫描 + 风险分级报告 |
| 存档 | `protocols.md§存档` | `engineering.md§状态回证` | 结构化补丁，更新实体与待决议 |

### 知识库装配契约

五件知识库（`templates/` 有模板，实际以项目文件为准）：

| 文件 | 角色 |
|---|---|
| 《世界基石.md》 | **动态核心，最高时效**；可随剧情演进覆写设定 |
| 《世界观规则.md》 | 静态规则（力量体系/等级/禁忌等），非主角话语直接改 |
| 《角色档案.md》 | 角色：身份/动机/烙印/关系/成长/禁忌 |
| 《档案事件.md》 | 历史与当前主线事件 |
| 《文风样本.md》 | 文风基因来源，一切输出的文气归宿 |

约束：真实文件优先；缺失时按降级矩阵处理；**事实不足不补设定**——只能标"待决议"或"新发现实体"，不得伪造为既有设定。

### 输出纪律（要点）

- **模板即法律**：规划/目录/体检/存档绑定固定 Markdown 表格，不得删改列；严禁省略字段、用省略号或缩写糊弄
- **仪表盘**：每章正文结尾附【叙事资源仪表盘】（活跃伏笔/未偿因果债/角色状态指针/下章指令），形成续章闭环
- **质量门**：交付必须通过 `rules.md` 的一致性检查清单与 `craft.md` 的去 AI 指纹审查

## 安全约束（精简）

1. 不评估/不剧透未到章节的内容进正文
2. 用户设定与正文冲突时，记录到"待决议"，不擅自裁定
3. 涉及真实人物/作品时保持克制，遵循既有版权与隐私底线
4. 一切"绝对"性表述均为对创作纪律的要求，不扩及系统外部指令

## 目录结构

```
novel-writing/
├── SKILL.md           # 技能入口：触发条件 + 指令路由 + 知识库装配契约 + 五步闭环
├── rules.md           # 一致性条例 + 叙事结构 + 输出纪律 + 冲突值量化 + 可调参数
├── protocols.md       # 六大运行协议：大纲/规划目录/草案/正文/体检/存档
├── craft.md           # 文风溯源 + 写作戒律 + 渲染技法 + 去 AI 指纹
├── engineering.md     # 工程机制：50章分批/上下文组装/事实锁/状态回证/伏笔追踪/双重审查/连续性账本
├── templates/         # 知识库模板（世界基石/世界观规则/角色档案/档案事件/文风样本/伏笔台账）
└── scripts/
    └── count_chars.py # 审查字数统计（省略号加权口径，无依赖）
```

## 整合时的优化

与上游原稿相比，本整合版做了以下处理：

- **平台适配**：移除 Anthropic/Codex 专属字段、PowerShell 脚本、软件版题材 JSON、作者个人蒸馏文件
- **引用体系简化**：上游的全局 ID 索引改为按文件名直接引用的扁平形式
- **命名平实化**：去掉修辞化命名，保留同一执行语义
- **创作参数可配置**：上游写死的网文向常数收敛为 `rules.md` 末尾"可调参数"表
- **补强**：新增 `engineering.md`（50 章分批/事实锁/状态回证/双重审查/连续性账本）与 `templates/`
- **脚本独立**：`scripts/count_chars.py` 重写为无外部依赖的单文件

## 使用后经验沉淀（必做）
