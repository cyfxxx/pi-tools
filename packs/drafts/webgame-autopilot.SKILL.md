# 网页游戏原型自主迭代

适用：用户以极简指令（"做一个 xxx 游戏""自行迭代""继续""运行，我测试一下"）驱动网页游戏开发，不希望被过程性提问打断。

## 步骤

1. **概念完善**：用户给出题材/玩法关键词后，先查本地 packs 已有技能（如 gamedev），再 web_search 同类开源项目与游戏开发经验，汇总成设计要点后再动手，不裸写。
2. **锁定卖点**：用户明确提出的差异化要求（如"物品合成/技术发展贴近真实"）按原话固化进设计，后续迭代不得自行偏离或削弱。
3. **无人值守原型**：用户离开前授权"自行迭代"时，直接产出可运行的测试原型；以"随时能跑起来"为交付标准，不阻塞等待确认。
4. **验收回路**：用户返回要求测试时，提供可运行入口（本地服务或打开入口文件），收集反馈作为下一轮迭代输入。
5. **按反馈迭代**：结构性决策（如图层划分：大世界概览图简略显示 + 局部文明图详细显示）严格按用户描述实现，一次做对。
6. **新机制先研究**：需引入新机制（如插件/mod 动态改变游戏内容）时，先调研通用实现方案，再落地到本项目。
7. **版本管理**：阶段性成果推送到用户指定的 GitHub 仓库，保持远端与本地同步可测。
8. **完整性自评收尾**：授权"直到完整"时持续自主计划/执行/决策/测试，遇到问题自行查资料解决；自评无大的必要修改后停止，一次性汇总改动与遗留事项汇报。
