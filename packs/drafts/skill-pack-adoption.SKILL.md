# 第三方技能包引入与验收

## 适用场景

从 GitHub 找到外部技能包（zip release），需要安全地纳入本机 packs 并确认真正可用。典型对象：封装某平台 CLI 的技能包（如微信开发者工具类）。

## 步骤

### 1. 选包与下载

- 在 GitHub 按关键词搜索，优先选择：有正式 release tag、近期仍有提交、issue 有人回应的仓库。
- 下载 release zip 到本地，不要直接执行来源不明的安装脚本。

### 2. 解压审查（安装前必做）

- 解压后逐项检查：
  - `SKILL.md` 存在且 frontmatter（name/description）合法；
  - 脚本内容无危险操作（递归删除、数据外传、混淆代码）；
  - 依赖清单明确、可审计。
- 审查不合格直接丢弃，不进入下一步。

### 3. 安装

- 包体放入 `~/.pi/packs/<name>/`，保持原目录结构。
- 外部 CLI 依赖单独安装，并以 `<cli> --version` 输出版本号作为就绪判据；版本号都出不来就不继续。

### 4. 对照官方文档核验命令面

- 打开目标平台官方 CLI 文档，逐一核对技能包封装的子命令与参数是否与当前官方版本一致（版本漂移是常见故障源）。
- 一并完成平台侧前置条件。例：微信开发者工具 CLI 需先在 设置→安全设置 中开启「服务端口」，否则所有 CLI 命令连接失败。

### 5. 冒烟测试

- 新建一个能被目标平台识别的最小示例工程（最小合法文件集即可）。
- 只跑 1-2 条核心命令验证完整链路；通过后删除临时工程。

### 6. 归档

- 写使用总结，更新 packs README / 变更记录。
- git 提交并推送；remote 含 token 时先恢复无凭证 URL 再 push。
