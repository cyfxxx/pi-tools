# pi-voice 唤醒词故障诊断与修复

## 适用症状
- 正常录音可转写输出，但进入唤醒监听后说唤醒词无反应，统计显示 0 次。
- 修改 pi-voice 代码重启后行为不变。
- pi 启动即崩溃且调用栈指向 pi-voice。

## 诊断流程（先建反馈回路）
1. 验证基线：手动录音→转写，确认麦克风与 ASR 模型正常。基线不通先修基线，勿直接猜唤醒逻辑。
2. 单测唤醒链路：进入监听，说唤醒词，观察统计计数与日志输出。
3. 按三类故障面分流：采集通道丢数据 / 唤醒模型缺陷 / 回调触发时机错误。

## 已确认的坑与修复
### 1. stdout pipe 在扩展沙箱下不可靠（最常见）
- 症状：唤醒进程存活、录音正常，但唤醒事件永远收不到，统计恒为 0。
- 根因：sherpa-onnx KWS 子进程经 stdout pipe 上报结果，在 pi 扩展沙箱下 pipe 传输不可靠，事件静默丢失。
- 修复：唤醒进程加 `--file-format=wav` 让检测结果落盘，扩展侧轮询读文件代替解析 stdout。

### 2. 加载期调用 sendMessage 导致启动崩溃
- 根因：扩展加载阶段 runtime 未绑定，sendMessage 是抛错桩；若加载期直接 launchWakeSession 且回调触碰 sendMessage，整个 pi 启动崩溃。
- 规则：依赖 runtime 的 API 一律延迟到首次用户交互或显式开关触发，禁止模块顶层/load 回调同步调用。

### 3. KWS 3.3M 拼音模型自身缺陷
- 该模型存在误检/漏检问题。排查代码前先换模型或调阈值交叉验证，避免误诊。

## autoWake 后台监听实现要点
- 目标：pi 启动后在后台持续监听唤醒词，支持手动关闭。
- 结构：配置项放 pi-voice config/index.ts，逻辑在 core.ts；开关走扩展现有 slash 命令体系（遵守 ≤2 命令约定，用子命令参数）。
- 关闭时须终止唤醒子进程并清理文件轮询定时器，防止僵尸进程。

## 验证清单
- 重启 pi（config/index.ts、core.ts 等扩展源码改动均不热载）。
- 说唤醒词 → 统计计数 > 0 → 后续动作触发。
- 手动开/关各一次，确认子进程与定时器清理干净。
- 连续 10 次以上唤醒无误判漏判再交付。
